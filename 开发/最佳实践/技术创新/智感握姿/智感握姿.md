# 智感握姿

更新时间：2026-06-12 07:22:00

来源：https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-smart-reach

随着大屏和折叠屏设备的普及，用户单手握持设备时，拇指难以覆盖整个屏幕区域，尤其是位于屏幕顶部与侧边的交互元素往往难以触及。为有效解决这一痛点，HarmonyOS系统提供了[智感握姿](https://developer.huawei.com/consumer/cn/doc/design-guides/smart-reachability-0000002556657823)能力。该能力能够感知用户当前的握持手势（左手或右手），并自动将核心交互控件迁移至拇指的可达范围内，从而显著提升单手操作的便捷性。智感握姿示例图如下图所示：

本文将从智感握姿的概念与适用场景出发，结合新闻阅读应用示例，详细讲解如何在HarmonyOS应用中接入智感握姿能力，具体包括组件原生适配与自定义握持感知两种方案。
 

#### 智感握姿介绍

 

#### 什么是智感握姿

智感握姿是HarmonyOS系统提供的一项交互增强能力。系统通过设备传感器感知用户当前的握持手（左手或右手），并将该状态暴露给应用层。应用可以根据握持手信息，动态调整UI布局，将操作按钮、导航栏等关键交互元素移动到用户拇指舒适可达的区域。
 
这一能力的核心价值在于：
 
- 降低操作负担：用户无需调整握持姿势或使用双手，即可轻松触达核心交互元素。
- 提升单手体验：针对折叠屏及平板的单手操作可达性问题，智感握姿提供了基于握持手势的界面自适应能力。
- 智能自适应：握持状态变化时，UI自动跟随切换，无需用户手动设置。

 
 

#### 适用场景

智感握姿在以下场景中能显著提升用户体验：
  
| 场景 | 说明 |
| --- | --- |
| 浮动按钮/面板自动切换 | 悬浮操作按钮、浮动面板根据握持手自动左右切换位置，始终处于拇指可达区域。 |
| 单手模式UI适配 | 在单手握持时，将关键操作区域（如底部导航、侧边栏）调整到握持手一侧。 |
| 阅读应用翻页按钮优化 | 翻页按钮、阅读工具栏根据握持手动态调整位置，避免手指跨越整个屏幕操作。 |
 
 
 

#### 应用接入智感握姿方案

在HarmonyOS中，接入智感握姿主要有两种方案：
 1. 组件原生适配：使用系统组件（如[HdsTabs](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdstabs)）内置的智感握姿支持，通过简单配置即可实现。
2. 自定义握持感知：通过监听系统握持手状态变化，自行控制UI布局的动态调整。
 
 

#### 方案一：组件设置智感握姿

部分[UI Design Kit](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ui-design-introduction)已经内置了智感握姿的支持，开发者只需通过属性配置即可启用。以 [HdsTabs组件](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdstabs)为例，当设置[barOverlap](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdstabs#baroverlap)启用悬浮态时，通过[barFloatingStyle属性](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdstabs#barfloatingstyle)中的adaptToHandedness设置为true，即可实现底部页签栏自动跟随握持手切换位置，无需手动监听握持状态。
 
> [!NOTE]
> 这种方式的优势在于零代码逻辑。组件内部已经处理了握持状态监听和位置切换，开发者只需通过简单的属性配置即可获得智感握姿能力。

 
```text
HdsTabs({ controller: this.controller }) {
  // TabContent...
}
.barOverlap(true)
.vertical(false)
.barPosition(BarPosition.End)
.barFloatingStyle({
  barBottomMargin: 36,
  adaptToHandedness: true
})
```
 
 

#### 方案二：自定义感知握持状态实现智感握姿

当系统组件未开放相应属性或参数，使得方案一无法满足需求时，开发者可以利用HarmonyOS的[动作感知能力](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion)，感知用户握持手机的手势（左手/右手/双手/未握持），根据握持状态动态调整UI布局（如自定义浮动面板位置、侧边按钮偏移等）。开发者可通过以下步骤自行实现智感握姿：
 1. 配置权限在module.json5中声明获取用户动作所需的权限：

  
```json
{
  "module": {
    "requestPermissions": [
      {
        "name": "ohos.permission.DETECT_GESTURE"
      }
    ]
  }
}
```

2. 订阅握持手变化

  通过[动作感知能力](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion)中的[motion.on('holdingHandChanged')](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion#motiononholdinghandchanged-20)，订阅握持手状态变化。其中，[HoldingHandStatus](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion#holdinghandstatus20)支持未握持（NOT_HELD）、左手握持（LEFT_HAND_HELD）、右手握持（RIGHT_HAND_HELD）、双手握持（BOTH_HANDS_HELD）以及未识别（UNKNOWN_STATUS）状态。
```text
import { motion } from '@kit.MotionKit';

handleHoldingHandChange: Callback<motion.HoldingHandStatus> = (status: motion.HoldingHandStatus) => {
  // Updating the UI based on the hand holding status.
}

motion.on('handednessChange', this.handleHoldingHandChange);

// Unsubscribe upon destruction
motion.off('handednessChange', this.handleHoldingHandChange);
```

3. 添加动画，根据握持手位置切换组件位置获取到握持手状态后，通过动画平滑地切换组件位置：

  
```text
@Local handedness: motion.Handedness = motion.Handedness.NONE;

build() {
  Row() {
    // Floating Panel
    FloatPanel({ handedness: this.handedness })
  }
  .animateTo({ duration: 300, curve: Curve.EaseInOut }, () => {
    // Updating the UI based on the hand holding status.
  })
}
```

 
 

#### 新闻阅读界面适配智感握姿

本示例以新闻阅读应用为场景，完整演示了智感握姿适配：通过HdsTabs实现底部悬浮导航，结合瀑布流内容布局，使页签栏能够智能跟随握持手自动切换位置，同时通过通过[动作感知能力](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion)中的[motion.on('holdingHandChanged')](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-awareness-motion#motiononholdinghandchanged-20)，实时感知握持手状态，动态调整侧边按钮位置以提升单手操作体验。

```ArkTS
HdsTabs({ controller: this.controller }) {

    }
    .tabBar(repeatItem.item)
  })
}
```

#### 常见问题

 

#### 智感握姿在所有设备上都支持吗？

 
不是。智感握姿依赖设备硬件传感器的支持，部分设备可能不具备握持检测能力。建议在应用中做好兼容处理，当设备不支持时提供默认布局。可以通过功能提示弹窗告知用户"当前机型暂不支持该功能"。自定义握持感知方案可以使用[checkAccessToken](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-abilityaccessctrl#checkaccesstoken9)判断应用被授予ohos.permission.DETECT_GESTURE权限状态，如果设备不支持，将返回801错误码。具体可参考获取握持手状态开发指导的[约束与限制](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/motion-guidelines#约束与限制-1)。
 

#### 如何适配兼容性，最低支持哪个API版本？

 
HDS组件最低从API23开始支持。如果应用需要兼容更低版本，应使用自定义握持感知方案，通过motion.on('handednessChange')监听握持状态变化。需注意获取握持手状态最低从API20开始支持，详情查看[获取用户动作开发指导](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/motion-guidelines)。
 

#### 握持手切换时如何避免UI闪烁？

 
建议在握持手状态变化时使用animateTo添加过渡动画，设置合理的动画时长（推荐200-400ms）和缓动曲线（推荐Curve.EaseInOut），使位置切换平滑自然。
 
```text
import { motion } from '@kit.MultimodalAwarenessKit';

// Listening for changes in grip hand state
motion.on('holdingHandChanged', (data: motion.HoldingHandStatus) => {
    animateTo({
        duration: 300,
        curve: Curve.EaseInOut
    }, () => {
        // UI update logic
        this.uiPosition = data === motion.HoldingHandStatus.LEFT_HAND_HELD ? 
            Position.Left : Position.Right;
    });
});
```
