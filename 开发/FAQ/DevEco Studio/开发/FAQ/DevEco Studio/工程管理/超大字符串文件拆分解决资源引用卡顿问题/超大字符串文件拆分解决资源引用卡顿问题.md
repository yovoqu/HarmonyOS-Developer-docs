# 超大字符串文件拆分解决资源引用卡顿问题

更新时间：2026-06-26 07:47:42

来源：https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/faqs-project-management-32

#### 问题现象

开发者资源相关文件全部放在一个单独的har内，总共五种语言，每种大概七千左右的key、value键值对。在工程其他的module中，借助资源访问符访问字符串，IDE会卡顿加载出来耗时较长，基本点不动。
 

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/67/v3/qEIkDWzsQbKTRaVTXxVuhg/zh-cn_image_0000002628567962.png?HW-CC-KV=V1&HW-CC-Date=20260811T005516Z&HW-CC-Expire=86400&HW-CC-Sign=16B0283EFC404EAE7FEFC2720BD2A8B56F06BDB75F3BC59F416916DBBB8B76C7)

 
 

#### 背景知识

字符串资源文件string.json，超过一定大小，会导致IDE加载键值对慢，匹配转圈，本地测试超28000行（2.56M左右）会复现卡顿，建议超大资源文件做拆分。
 
 

#### 解决方案

如果存在字符串资源文件string.json超大的情况，可以考虑做文件拆分，具体操作如下：
 1. 右键element，选择New，然后选择Element Resource File。

  
![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/5d/v3/mQndV6xCQFWjU_RROv4R0Q/zh-cn_image_0000002658927285.png?HW-CC-KV=V1&HW-CC-Date=20260811T005516Z&HW-CC-Expire=86400&HW-CC-Sign=61101F5DFD19A517DB31BDB1A5CC0B330563308031DF1CF60A0FA7F4B1B6ED41)

2. File name写与string不一样的名称就可以了，比如string1，Root element选择string。

  
![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/28/v3/d6sOxzwEQnyjaVKEdrW4OQ/zh-cn_image_0000002658807329.png?HW-CC-KV=V1&HW-CC-Date=20260811T005516Z&HW-CC-Expire=86400&HW-CC-Sign=6940F495BC02FC79142C125B78BBAC23652FB339DE6A2F3479D376559C574E18)

3. 在新建的string1.json文件中新增键值对（如test_string_new），其他地方使用时，只要大小符合规范IDE很快会加载出来。
