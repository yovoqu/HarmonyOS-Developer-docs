# 超大字符串文件拆分解决资源引用卡顿问题

更新时间：2026-06-26 07:47:42

来源：https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/faqs-project-management-32

#### 问题现象

开发者资源相关文件全部放在一个单独的har内，总共五种语言，每种大概七千左右的key、value键值对。在工程其他的module中，借助资源访问符访问字符串，IDE会卡顿加载出来耗时较长，基本点不动。
 

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/67/v3/qEIkDWzsQbKTRaVTXxVuhg/zh-cn_image_0000002628567962.png?HW-CC-KV=V1&HW-CC-Date=20260723T013912Z&HW-CC-Expire=86400&HW-CC-Sign=1B61B63F80901FFCC255F092259E2C30D3F6285CB46AC059940052FD801C90FD)

 
 

#### 背景知识

字符串资源文件string.json，超过一定大小，会导致IDE加载键值对慢，匹配转圈，本地测试超28000行（2.56M左右）会复现卡顿，建议超大资源文件做拆分。
 
 

#### 解决方案

如果存在字符串资源文件string.json超大的情况，可以考虑做文件拆分，具体操作如下：
 1. 右键element，选择New，然后选择Element Resource File。

  
![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/5d/v3/mQndV6xCQFWjU_RROv4R0Q/zh-cn_image_0000002658927285.png?HW-CC-KV=V1&HW-CC-Date=20260723T013912Z&HW-CC-Expire=86400&HW-CC-Sign=18318BA55317820364628A558D585D5AB2862773A440E8A76D994A8F6F8391DA)

2. File name写与string不一样的名称就可以了，比如string1，Root element选择string。

  
![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/28/v3/d6sOxzwEQnyjaVKEdrW4OQ/zh-cn_image_0000002658807329.png?HW-CC-KV=V1&HW-CC-Date=20260723T013912Z&HW-CC-Expire=86400&HW-CC-Sign=DEFC3D1863B98A1FFB973D027E937B29885FD374CE2F3A159F82FEB58B9D034D)

3. 在新建的string1.json文件中新增键值对（如test_string_new），其他地方使用时，只要大小符合规范IDE很快会加载出来。
