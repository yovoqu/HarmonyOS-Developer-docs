# 目录划分与文件存放规则

> **经验来源**：2026-06-04 全量文档更新时，因不遵循现有目录层级导致 51 篇新文档路径错误，经历多次修正后总结本规则。

## 核心原则

**目录结构必须完全复制官网导航树层级。** 不能"简化"或"打平"树路径——现有文档已经按树路径组织了多层结构，新文档必须遵循同样的层级。

## 各 Catalog 的目录结构

### harmonyos-guides → `开发/指南/开发/`

三层结构：

```
开发/指南/开发/
├── {Section}/                         ← 树路径第1层：大类（应用框架、媒体、系统、AI …）
│   ├── {Kit名称}/                     ← 树路径第2层：Kit/服务名
│   │   ├── {子目录}/                  ← 树路径第3+层：可能有多级子目录
│   │   │   └── {文档名}.md
│   │   └── {文档名}.md               ← 直接在 Kit 下的叶子文档
│   └── {文档名}.md                   ← 直接在 Section 下的叶子文档（树路径2层以内时）
```

**Section 映射**（树路径第1层 → 本地目录）：

| 树路径第1层 | 本地目录 |
|------------|---------|
| 应用框架 | `开发/指南/开发/应用框架/` |
| 媒体 | `开发/指南/开发/媒体/` |
| 系统 | `开发/指南/开发/系统/` |
| AI | `开发/指南/开发/AI/` |
| 应用服务 | `开发/指南/开发/应用服务/` |
| 图形 | `开发/指南/开发/图形/` |
| NDK开发 | `开发/指南/开发/NDK开发/` |
| 一次开发，多端部署 | `开发/指南/开发/一次开发，多端部署/` |
| 自由流转 | `开发/指南/开发/自由流转/` |
| 应用开发准备 | `开发/指南/开发/应用开发准备/` |
| 编写与调试应用 | `开发/指南/开发/`（没有对应 Section，放在根或映射到应用框架） |

## 路径生成算法

从 API 树路径生成本地文件路径的步骤：

1. **获取完整的树路径数组** `["应用框架", "ArkUI（方舟UI框架）", "UI开发 (基于NDK构建UI)", "使用文本", "使用Text组件"]`
2. **从 catalog 确定根目录**：`开发/指南/开发/`
3. **逐层匹配已有目录**（从根开始）：
   - 先尝试**精确匹配**目录名
   - 再尝试**规范化匹配**（`（`↔`(`、`／`↔`/`）
   - 再尝试**包含匹配**（子串关系）
   - 都失败则**停止**，文件放在已匹配的最深层目录
4. **叶子是文件名**：`"使用Text组件.md"`
5. **如果某层目录不存在**：文件放在上一层已存在目录的根，**不要跳到兄弟目录**

### ⚠️ 常见陷阱

- **通用文件名**（`简介.md`、`环境准备.md`、`Functions.md`）出现在多个不同子树中——**必须用树路径区分，不能"选最深的"**
- **API参考的 manifest 只有一个**，entry 中 `section` 字段 = 第一层子目录名
- **不要跨 catalog 放文件**：harmonyos-guides 的文档不应放到 best-practices 目录
- **cross-referenced docs**：有些文档同时在 guides 和 best-practices 中，各自独立存放
- **FAQ 子目录也遵循树路径**：如 `开发 > DevEco Studio > AI辅助编程 > 文档` → `FAQ/DevEco Studio/AI辅助编程/文档.md`，不可省略中间层级
- **best-practices 也有多层结构**：如 `一次开发，多端部署 > 多设备界面开发 > 兼容方案 > 平行视界` → `多设备开发/一次开发，多端部署/兼容方案/平行视界.md`

## manifest.json 规范

| Catalog | Manifest 位置 | 是否有 section 字段 |
|---------|-------------|-------------------|
| harmonyos-guides | 每个 Section 目录内 | 是（同 Section 名） |
| harmonyos-references | `开发/API参考/manifest.json` 一个 | 是 |
| harmonyos-faqs | 每个子目录内 | 否（或空字符串） |
| best-practices | 每个子目录内 | 否 |
| harmonyos-releases | `开发/版本说明/manifest.json` 一个 | 否 |
| design-guides | 每个子目录内 | 否 |

## 差异检测与新增流程

```
1. getCatalogTree 获取官网完整目录树 → 所有 slug
2. 对比本地 manifest → 找出新增 slug
3. getDocumentById 获取标题 + 更新时间
4. 按树路径确定本地文件路径（见上）
5. fetch_docs.py 拉取正文、转 MD、写入
6. 更新对应 manifest.json
7. 去重检查（同 slug 不能在同 manifest 出现两次）
```
