# 下线文档处理规范

> **经验来源**：2026-07-01 全量文档更新时，发现官网目录树中已删除但本地仍保留的文档，制定本规范。

---

## 核心原则

**官网已下线的文档仍在本地仓库保留**，不删除。但必须在文档头部明确标记其下线状态，以便读者区分"当前有效文档"和"历史存档文档"。

## 标记格式

在 `更新时间` 行末尾追加 `（官网已下线）`：

```markdown
# 文档标题

更新时间：2026-06-12 06:54:11（官网已下线）

来源：https://developer.huawei.com/consumer/cn/doc/harmonyos-references/slug
```

- 标记追加在时间戳**同一行**，不用单独一行
- 仅更新元数据行，不修改正文内容
- 已标记的文档**不再重复标记**

## 检测方法

通过对比本地 manifest 与官网 `getCatalogTree` API 返回的叶子节点 slug 集合来确定：

```python
official_slugs = extract_slugs_from_catalog_tree(catalog)
local_slugs = set(manifest_slugs)
removed_slugs = local_slugs - official_slugs  # 已下线
new_slugs = official_slugs - local_slugs       # 新增
```

## 标记脚本逻辑

```python
for slug in removed_slugs:
    filepath = resolve_local_file_from_manifest(slug)
    content = read_file(filepath)
    # 检查是否已标记，避免重复
    if "（官网已下线）" in content:
        continue
    # 在 更新时间 行末尾追加标记
    new_content = re.sub(
        r'(更新时间：.+)',
        r'\1（官网已下线）',
        content, count=1
    )
    write_file(filepath, new_content)
```

## 为什么保留而非删除

1. **历史参考价值**：已下线 API 的文档对维护旧版本应用仍有参考意义
2. **Git 历史可追溯**：删除会丢失上下文，标记保留可随时查看
3. **避免误删**：部分文档可能因官网临时调整而短暂消失，标记比删除更安全
